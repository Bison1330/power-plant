# FM-17 and Finding 14 — runtime 225 dry run against the live dev chain

Runtime under test: `dev-ops/runtimes/vitreus_power_plant_testnet_runtime-225.compact.compressed.wasm`
built from the fork tip (sha256 `cf406a5969c89268a193cd91a364188a86ee070467c8a5a2e6cba901665867a0`; `…-225-try-runtime…` for the dry run). Live chain: spec 224.
Rollback: `…-224…`.

What 225 carries:

- **FM-17 (was the launchpad's "FM-14"): asset-id squatting.** `create_launch` walks a monotonic
  `NextAssetId` cursor to the first free asset id instead of failing `AssetIdTaken` on a squatted
  slot — the exact state live on the chain, where the next slot was taken and creation was blocked.
  No storage migration; the cursor defaults to `LaunchAssetBase + NextLaunchId`.
- **vitreus-dex SECURITY_AUDIT Finding 14: a sub-ED routed fee slice.** `do_swap` leaves a sub-ED
  slice in the pool when its recipient has no account; the launchpad folds a sub-ED curve treasury
  slice into the protocol share. `FundDexFeeEscrow` mints the ED into the fee escrow once so the
  window never opens.

## The storage diff (14 keys)

`FundDexFeeEscrow` creates the fee-escrow account (a new `System::Account`, its providers) and mints
its ED, so `Balances::TotalIssuance` rises by one ED; plus `System::LastRuntimeUpgrade` → 225, the
`LaunchTreasury::VaultFunded` re-set, and the permanent per-upgrade writes (`:ethereum_schema`,
`XcmPallet::CurrentMigration`). No launch/pool/treasury record changes shape.

## After the real `setCode`

`system.lastRuntimeUpgrade` 225. `create_launch` succeeds on the currently-squatted slot (walks past
it), and a swap or curve buy whose routed slice is below ED no longer fails with `BelowMinimum`; the
fee escrow now exists, so later fees of any size route to it.
